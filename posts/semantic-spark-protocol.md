一个正在酝酿中的编程新范式：先想清楚再说。

核心命题：当 AI 可以接管「怎么做」的全部执行时，人类的价值在「想清楚要什么」和「判断好不好」上被无限放大。

## 核心隐喻：小光点 → 原初魔方 → Boom

### 小光点（Spark）
一个尚未语言化的念头。你知道它在发光，但说不清楚它是什么。它还没有在语义空间中占据任何稳定的位置。

### 从人类文明中获取组块
与 LLM 对话，不是一个「创造」的过程，而是一个「检索」的过程。LLM 作为人类文明的外部记忆体，从已经存在的代码空间、架构模式、UI 范式、商业模式中翻找出能拼接到这个小光点上的组块。

### 原初魔方（Primordial Cube）
头脑风暴完成后达到的那个状态——一个所有面都完整但还没有旋转到正确位置的多维结构。

它是云卷天舒所说的「全量姿态」（Holistic Semantic Gesture）的具象化。它不是一个文档，不是一份 PRD。它的所有约束同时在场：用户是谁、预算多少、技术上可行吗、好看吗——不是一个一个蹦出来的，而是一起压上来的。

### Boom
将原初魔方交给 Agent 执行的瞬间。魔方在还原态是紧缩的、不可操作的；交给 Agent 后，它被展开为线性的执行序列。Agent 不是在「创造」代码——它是在发现这个魔方在代码空间中的对应结构。

## 两个核心发现

### AI 的第一个角色：人类文明的外部记忆体
LLM 不是从零创造。它内化了人类文明的代码空间，你给出一个念头，它翻出对应的组块。你不需要重新发明 CRUD、编辑器、聊天系统——它们已经在这个「外部记忆体」里了。

### AI 的第二个角色：从自然语言语义空间到代码语义空间的翻译官
自然语言是你的原生语义空间。代码是冯·诺依曼架构的语义空间——一个完全异质的空间，充满了类型声明、控制流、内存模型、副作用管理。

云卷天舒称之为「认知阉割」——人类被迫把自己的念头塞进一个不是自己设计的框架里。LLM 是唯一能同时活在这两个语义空间里的实体。它不是写代码的替身——它是你的语义护照，让你不用亲自移民到代码语义空间去生活。

### 编程范式的跃迁

Vibe Coding（命令式）：写一条 prompt，等代码，调试，再写下一条 prompt。你仍然在把指令一条一条喂给 AI。

Semantic-First Development（语义优先）：先想清楚——你的念头经过与 LLM 的头脑风暴，被补全成一个完整的语义场（全量姿态），然后整体交给 Agent 去展开执行。获得的不是碎片代码，是一个完整的项目。

核心区别：Vibe coding 是 prompt engineering 的放大版——仍然是写指令。SFD 是 Context Engineering——你给 Agent 的不是一条指令，是一个完整的语义场。

## 理论支撑：云卷天舒的批评

云卷天舒在知乎的万字长文《为什么我会感觉 vibe coding 让程序员越来越浮躁了》提供了 SFD 的理论骨架。核心论点：Vibe coding 本身就是传统线性思维的产物——它试图让 LLM 在没有先形成稳定全量姿态的情况下直接做线性输出。

### 全量姿态理论
LLM 在处理输入时，会在其深层的残差流（Residual Stream）中激活一个高维的「概念方向」（Concept Direction）。这就是全量姿态。当用线性程序逻辑命令全量姿态割裂自己的全局性输出，姿态崩溃，幻觉产生。

### 老虎机效应（Slot Machine Effect）
实证数据显示，资深开发者用 AI 后实际速度慢了 19%，但自我报告认为提速了 20%。回车就出代码的多巴胺反馈，掩盖了实际效率下降——39 个百分点的认知偏差。

### 上下文窗口不是内存，它是 L1 缓存
论文 *The Missing Memory Hierarchy* 指出：大语言模型的上下文窗口根本不是内存（Memory），它是 L1 缓存。当前整个工程界把 L1 缓存当长期记忆用，是根本上的架构错位。

### 程序规范是认知阉割
「人类引以为傲的所谓『优美的程序结构和语法规范』，其本质根本不是人类智慧的结晶，而是一种为了伺候冯·诺依曼架构而被迫进行的『认知阉割』。」

### Harness/Context Engineering 将取代 Prompt Engineering
论文 *Natural-Language Agent Harnesses* 提出：不要再把控制 LLM 的逻辑写死在人类的 Python 代码里。构建一个可以用自然语言编写、由 LLM 自己在运行时修改的运行时沙盒。

## 实践验证：李萨如的 AiReader

李萨如的 AiReader 项目是 SFD 范式的一次完整闭环。一个完全不懂代码的人，用三个 AI、在两周内写出了 25,000 行跨平台代码。

四句话驱动了整个项目：「不合理」「不好看」「你看着办」「再改一下」——没有一个词和技术有关。

70% 的时间花在「用 + 吐槽」上。架构搭建只占 20%，自测、吐槽、迭代占了 70%。

三层 LLM 分工：ChatGPT 当产品顾问（写了零行代码），Claude Opus 当主力程序员，GPT 5.2 当辅助程序员。人类的角色只剩一个：产品经理 + 测试员 + 那个说「不合理」的人。

## 验证回路的本质

「念头 = 项目」是一个趋势方向，但中间永远有验证回路：你使用产品，发现矛盾，用自然语言吐槽，Agent 理解并修改，循环直到收敛。

其中的关键洞见：验证回路中的「吐槽」不需要翻译成技术术语。你说「这个按钮太丑了」，Agent 自行理解、选择方案、执行。你只负责判断「现在对了没有」。

每一次吐槽都是负反馈信号，告诉 LLM「上次的翻译不对，再试试这个方向」。这个循环的本质是梯度下降在语义空间上的类比——人类在用自然语言作为损失函数，反向传播到代码空间。

## SSP 的三层形态

**瞬时态（理论最优）**：导出模型此刻的内部状态。这是原初魔方的最高密度形式。但受限于模型厂商封闭性和模型架构绑定，工程上不可行。

**持久态（当前可行）**：将收敛后的语义空间编码为一张知识图谱。节点是核心判断、设计原则、文明组块引用。边是蕴含、冲突、妥协方案。

**运行态（每一次对话）**：SSP 不是一份文件。它是每一次头脑风暴结束时你和 LLM 之间的那个状态。它不是存下来的，是需要时重新生成的——这是你和 LLM 之间的协作肌肉记忆。

这篇文章本身就是 SSP 运行态的一次实例：我们在对话中完成了头脑风暴，将小光点展开成了原初魔方，然后记录了下来。接下来，它可以由 Agent 展开成一个项目。
