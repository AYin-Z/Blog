五月初（准确说是五月四日前后），我把 Hermes Agent 部署到了自己的服务器上。从那时起到现在，半个月出头，做了一个完整的 AI 基础设施。写一篇记录。

## 开局：一个 Agent 的诞生

Hermes Agent 是 Nous Research 的开源项目——一个可高度自定义的 AI 助手框架。部署过程没有什么特别，clone 仓库、装依赖、配 config、跑起来。真正的工程量在部署之后。

底模选了 DeepSeek v4 Flash，因为快、便宜、中文好。后来也接了本地模型（Carnice-MoE-35B 通过 llama.cpp 跑在 8081 端口）作为 offline fallback。

## 记忆系统：MemOS

初期最折磨人的部分。Hermes 本身没有持久记忆，需要外挂。最终方案是 MemOS——一个 Docker 三件套：

- **MemOS API**（8000 端口）——记忆的读写接口
- **Neo4j**（7474 端口）——图数据库，存实体关系
- **Qdrant**（6333 端口）——向量数据库，语义检索

对接到 Hermes 的 HTTP adapter，使它能记住跨会话的用户信息。中间修了三次连通性问题，包括一个因为忘记 `sudo` 而白折腾半小时的经典坑。

## 平台接入：六个月群的管家

Hermes 现在同时挂在六个平台上：

| 平台 | 方式 | 状态 |
|------|------|------|
| **飞书** | 自建应用 WebSocket | 主力工作流 |
| **微信** | iLink 协议 | 主力日常（但常被限流） |
| **QQ** | NapCat Docker | 社交/素材日报 |
| **Telegram** | Bot API | 海外通讯 |
| **163邮箱** | POP3 轮询 | 邮件接收（IMAP 被墙） |
| **Web API** | Hermes WebUI | 访客入口 |

其中 NapCat QQ 的配置踩得最深——Docker host 网络模式、WebSocket 18801 端口、扫码登录、session 持久化。现在每天 20:00 自动给朋友推送议论文素材。

## 浏览器自动化：Camofox

目前最有趣的组件。一个 Firefox 实例跑在服务器上，通过 REST API 控制。核心能力：

- **指纹伪装**：Canvas/WebGL/音频指纹随机化
- **Cookie 持久化**：知乎、B站、GitHub、小红书、微信读书等五个网站的登录态注入
- **操控 API**：打开标签页、导航、执行 JavaScript（`/tabs/{id}/evaluate`）

基于它，今天刚完成了知乎自动化发布服务——可以自动写文章、回答问题、发想法。

## 基础设施

整了一套完整的对外暴露方案：

- **Cloudflare Tunnel**：公网入口，绑定 `*.ayinserver.xin` 域名
- **CF Access**：管理后台用邮箱验证码保护
- **Mihomo**：系统级代理（TUN 模式），管理 DNS 和路由
- **Tailscale**：内网直连备用通道
- **Nginx**（8083 端口）：反向代理 8 个后端服务

`ayinserver.xin` 是公开的导航页，`hermes.ayinserver.xin` 是 AI 聊天入口（WebUI），`hermes-admin.ayinserver.xin` 是受保护的管理面板。

## MCP 工具链

Hermes 的 MCP 协议接入了五个外部工具：

| MCP | 用途 |
|-----|------|
| **12306** | 火车票余票查询 |
| **高德地图** | 路径规划、天气、地理编码 |
| **Tavily** | 网络搜索 + 网站爬取 |
| **Exa** | 进阶搜索（博客、公司页等） |
| **Playwright** | 浏览器自动化 |

每个都踩了一些配置坑——网络搜索的 API key 配置、12306 的站点编码查询、Playwright 在 mihomo TUN 模式下的下载问题。

## Skills 体系

写了 60+ 个自定义技能（skills），覆盖：

- 开发类：Vue 全家桶、TDD、代码审查
- 运维类：Docker 管理、系统健康检查、CF 管理
- 创意类：架构图、ASCII art、PPT 生成
- 学习类：公安学基础交互式问答
- 记账：自然语言转 hledger 双分录

每个 skill 都是一份结构化文档，包含触发条件、步骤、验证方式和踩坑记录。

## 系统韧性

服务通过 systemd 全家统一管理，失败自动重启。专门配置了耦合寄存器（耦合点清单，记录系统中任何改动可能波及的范围），因为 20+ 个服务相互依赖，改一个可能崩一片。

已经踩过的坑包括：
- 误杀 mihomo 进程导致全断网（DNS + TUN 路由丢失）
- write_file 覆盖整本账本（从此只准 patch 追加）
- 微信限流导致课堂提醒全部丢包（已启用飞书双通道备份）
- Camofox 连接断开后 session 不重建

## 正在做的事

这个系统还在长。今天刚完成的 zhihu-publish 服务是最近的一个节点——让 Hermes 能直接发布知乎内容，而不仅仅是阅读。

类名单词挑战、课堂自适应复习、照片自动分类……排着队等着。

两个星期前，这一切还是零散的代码片段、未连接的文档和"有空再说"的计划。现在它已经是一台日夜运行的机器了。

挺好的。
